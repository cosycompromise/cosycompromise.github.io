🔍 The basics

Malware analysis is the practice of studying a malicious file or program to understand what it does, how it works, and how to detect or stop it — useful for incident response, threat intelligence, and detection engineering alike.

Static analysis

Examining a sample without running it: looking at its file structure, strings, imports, hashes, and code, usually with a disassembler or decompiler.

  • Safer as a first step — nothing executes
  • Reveals structure, metadata, and possible packing/obfuscation
  • Can be limited by encryption or heavy obfuscation

Dynamic analysis

Running the sample in a controlled, isolated environment and observing its behaviour: file/registry changes, network calls, process activity.

  • Shows real runtime behaviour, including unpacked code
  • Requires a safe, isolated sandbox
  • Some malware detects sandboxes and hides its behaviour

🕯️ A gentle safety reminder

  • Only ever analyse samples inside an isolated virtual machine e.g., FlareVM, snapshotted before every run
  • Disable shared folders, disable or simulate network access (e.g. with INetSim or FakeNet)
  • Never analyse malware on a personal or production machine
  • Handle samples in line with your organisation's policy and local law

🧰 The toolbox

A cosy shelf of tools, sorted by what they're best at.

for static analysis

PEStudio Quick first look at a Windows executable's structure, strings, and indicators.
Ghidra Free disassembler and decompiler from NSA's research directorate.
IDA Free / IDA Pro Industry-standard disassembler for deep reverse engineering.
Detect It Easy (DIE) Identifies packers, compilers, and file types at a glance.

for dynamic analysis

Cuckoo Sandbox Open-source automated sandbox for behavioural analysis.
Process Monitor / Explorer Sysinternals tools for watching file, registry, and process activity live.
Wireshark Captures and inspects network traffic generated by a running sample.
Regshot Snapshots the registry before and after execution to spot changes.

online sandboxes & hunting

ANY.RUN / Hybrid Analysis Interactive, web-based sandboxes for quick behavioural triage.
VirusTotal Multi-engine scanning and community intelligence on a given sample or hash.
YARA Pattern-matching rules to identify and classify malware families.
capa Automatically identifies capabilities in a binary (FLARE team, Mandiant).

📖 A little glossary

Terms worth keeping in your back pocket. Tap one to open it.

IOC (indicator of compromise)
A piece of forensic evidence — a hash, IP address, domain, or file path — that suggests a system has been compromised.
Hash (MD5 / SHA-1 / SHA-256)
A fixed-length fingerprint of a file's contents, used to identify and share samples without sharing the file itself.
Sandbox
An isolated environment where a suspicious sample can run without risking the host system or network.
Packer / obfuscation
Techniques that compress or scramble a malware's real code to make static analysis harder and evade signature detection.
C2 (command and control)
The infrastructure an attacker uses to communicate with and issue instructions to infected machines.
Payload
The part of the malware that carries out its actual malicious action, once delivery and execution succeed.
Dropper / loader
A small program whose only job is to fetch and install a further, often larger, malicious payload.
Persistence
Mechanisms malware uses to survive a reboot or logoff, such as registry run keys or scheduled tasks.
YARA rule
A pattern-based rule describing byte sequences, strings, or traits used to identify a malware family.
Entropy
A measure of randomness in a file's data — unusually high entropy often hints at encryption or packing.
